## Loop 1 — Entry Points, Auth, HTTP/MCP Routing & Policy

### 1. [High] Batch trap misattribution across sequential tool calls in one HTTP update
- **Files:** `src/mcp.rs:386-404`, `src/lib.rs:188,261`, `src/bridge.rs:243-266`
- **Detail:** If `Tool1` (either an uncached `search_icp_canisters` or an awaited `execute_icp_script`) completes its `await`, writes its closing `AuditEntry`, and sets `bridge1.finish()`, and `Tool2` in the same HTTP batch traps *synchronously* before its own `await`, IC rolls back linear and stable memory to `Tool1`'s last resume point. That discards `Tool1`'s closing entry and `finish()` flag; cleanup drops `Tool1`'s `IcBridge` as `AuditStatus::Trapped`, falsely marking `Tool1` as trapped while erasing `Tool2` from the audit log. (`ACTIVE_RUNS` and `PENDING_RUNS` do not leak because linear memory rolls back `Tool1`'s future state too.)
- **Suggested fix:** Enforce at most one mutating/heavy tool (`execute_icp_script` or uncached `search_icp_canisters`) per consensus message, or commit/self-call per batched tool execution.

### 2. [Medium] Per-tool rather than per-message instruction budget & missing query search cap
- **Files:** `src/mcp.rs:362-404`, `src/bridge.rs:352-354`, `src/lib.rs:150-154,226-231`
- **Detail:** Each batched tool creates its own `IcBridge` with a fresh `base_instructions = instruction_counter()`. A single HTTP update carrying 1 `Execute` + 5 `Search` calls gives each tool its own `limits.max_instructions`, rather than enforcing one combined ceiling against IC's 40B limit. Inversely, `http_query` (`src/mcp.rs:362`) does not enforce `MAX_SEARCHES = 5`, allowing up to `MAX_BATCH = 50` cached searches in query mode while `http_update` rejects searches >5.
- **Suggested fix:** Track total `instruction_counter()` from message entry across `http_update` and apply `MAX_SEARCHES` uniformly in both `http_query` and `http_update`.

### 3. [Low] `execute_icp_script` upgrades via `http_query` even when `ACTIVE_RUNS == MAX_CONCURRENT_RUNS`
- **Files:** `src/mcp.rs:366`, `src/lib.rs:200,219-221`
- **Detail:** `http_query` always returns `HttpResponse::upgrade()` for `execute_icp_script` without checking `ACTIVE_RUNS`, forcing a paid consensus update round just to return `busy`.
- **Suggested fix:** Note that `http_query` runs on a single node (so `ACTIVE_RUNS` can be stale between query and update), or pre-check only if `certified_reads` is off and concurrency backpressure is acceptable as a hint.

### 4. [Medium] Missing `Origin` header check in MCP HTTP authentication
- **Files:** `src/mcp.rs:266-290`
- **Detail:** `mcp::authenticate` validates method (`POST`), path (`/mcp`), and bearer token, but ignores the HTTP `Origin` header (contrary to the MCP `2025-03-26` Streamable HTTP specification's DNS-rebinding MUST; partially mitigated in practice by ICP gateway `Host` routing).
- **Suggested fix:** Validate `Origin` when present (allow same-origin / configured allowlist or `null`-free explicit policy) and document gateway assumptions.

### 5. [Low] `set_allowlist` does not evict `DID_FAILED` or `DID_CACHE`
- **Files:** `src/lib.rs:296-304`, `src/bridge.rs:270-275`
- **Detail:** `remove_allowlist` calls `bridge::evict_interface(&canister)`, whereas `set_allowlist` leaves prior `DID_FAILED` (5m TTL) and `DID_CACHE` (1h TTL) entries intact when methods or target code change.
- **Suggested fix:** Call `bridge::evict_interface(&canister)` inside `set_allowlist` as well.

### 6. [Low] `apply` and `set_limits` do not validate `Limits` bounds
- **Files:** `src/lib.rs:46-48,307-309`, `src/bridge.rs:525`
- **Detail:** Neither `apply` nor `set_limits` bounds `max_instructions` (setting `>= 40_000_000_000` lets scripts hit IC's 40B hard trap before `budget_error` triggers) or `call_timeout_seconds` (`Some(0)` or `> 300`, passed directly to `Call::change_timeout`).
- **Suggested fix:** Validate/clamp `max_instructions` strictly below IC's per-message limit and validate `call_timeout_seconds` in `1..=300` (or reject invalid `Limits`).

### 7. [Low] `inspect_message` accepts malformed JSON / empty batches from valid token holders
- **Files:** `src/lib.rs:274-283`
- **Detail:** `inspect_message` checks only `mcp::authenticate`, not `parse_body` or method classification, so a token holder sending invalid JSON, empty arrays, or oversized batches still enters consensus `http_request_update` with no audit entry.
- **Suggested fix:** Mirror cheap structural checks (`parse_body` / batch bounds) in `inspect_message` before `accept_message()`.

### 8. [Medium] Single-language Cargo builds still advertise all 3 languages and default to JavaScript
- **Files:** `Cargo.toml:14-17`, `src/mcp.rs:125-127,217`, `src/demo.html:144,388,403,457`
- **Detail:** With `--no-default-features --features python` (or `rhai`), `tools_list` still advertises `enum: ["javascript", "python", "rhai"]` and `"default": "javascript"`, `parse_tool_call` defaults omitted `language` to `Language::JavaScript`, and `demo.html` renders all 3 `<option>`s and hardcodes `language: "javascript"` in the comparison panel.
- **Suggested fix:** Gate `tools_list` enum/default, `parse_tool_call` fallback, and `demo.html` options/comparison calls on enabled `#[cfg(feature = "...")]` runtimes.

## Loop 2 — Candid Bridge, Interface Cache & Search

### 9. [High] Silent Candid `opt` coercion to `null` on schema drift
- **Files:** `src/candid_bridge.rs:96-111`, `src/bridge.rs:216-227,284-289`
- **Detail:** `decode_reply` uses `set_skipping_quota(DECODING_QUOTA)` against `DID_CACHE` (1h TTL, no module-hash check) or `OVERRIDES` (no TTL). If a target canister upgrades and changes an `opt T` return field (e.g., `opt nat` -> `opt text`) or modifies fields inside an `opt record`, Candid decoding silently turns incompatible `opt` values into `IDLValue::None` -> JSON `null` while reporting `AuditStatus::Ok`.
- **Suggested fix:** Add strict subtype/compatibility checks or module-hash-based invalidation (`canister_status` / controller hook), or surface `OptReport` mismatches rather than silently emitting `null`.

### 10. [Medium] Single-arg `vec (vec T)` unwrapping ambiguity in `encode_args`
- **Files:** `src/candid_bridge.rs:70-73,116-123`
- **Detail:** `Value::Array(a) if a.len() == 1 && (a[0].is_array() || !is_array_like(&self.env, &func.args[0]))` unwraps `[[1, 2]]` into `[1, 2]` for a 1-arg `vec (vec T)` method, causing encoding to fail unless triple-wrapped (`[[[1, 2]]]`).
- **Suggested fix:** Require positional-wrapper unwrapping only when `!is_array_like(&self.env, &func.args[0])`, or inspect `a.len() == 1` depth cleanly against expected inner element shape.

### 11. [Low] `json_to_idl` blob hex parsing ignores uppercase `"0X"` and strips repeated `"0x"`
- **Files:** `src/candid_bridge.rs:247-249`
- **Detail:** `s.trim_start_matches("0x")` rejects `"0X..."` and silently accepts `"0x0xabcd"`.
- **Suggested fix:** Use `s.strip_prefix("0x").or_else(|| s.strip_prefix("0X")).unwrap_or(s)`.

### 12. [Medium] Unbounded keyword search loop in `search::render`
- **Files:** `src/search.rs:80-139`, `src/lib.rs:150-154`, `src/candid_bridge.rs:116-123`
- **Detail:** `search::render` splits `args.query` into unlimited whitespace tokens and evaluates `terms.iter().all(|t| hay.contains(t))` over all allowlisted methods without checking `query.len()`, term count, or instruction budget mid-loop (`run_search` checks only after `render`; `http_query` never checks). Also `is_array_like` and anonymous types in `collect_vars` (`src/search.rs:58-77`) lack explicit depth guards (bounded indirectly by `MAX_DID_BYTES` = 512 KiB).
- **Suggested fix:** Bound `args.query` byte length and keyword count (e.g. `<= 256` bytes / `<= 16` terms), enforce budget inside `render`, and pass a depth counter in `is_array_like` / `collect_vars`.

### 13. [Medium] Call-cap slot & duplicate fetch amplification in `fetch_did` / `IcBridge::call`
- **Files:** `src/bridge.rs:424-447,486,515-516`
- **Detail:** `candid()` reserves 1 slot while `fetch_did` can send 2 outbound calls (`canister_metadata` + `__get_candid_interface_tmp_hack`). Furthermore, concurrent `icp.call()` invocations (`Promise.all` / `asyncio.gather`) to the same uncached canister lack in-flight coalescing: `N` concurrent calls take `N` extra `candid` slots and dispatch up to `2N` redundant metadata/hack calls.
- **Suggested fix:** Account for both metadata + fallback messages in slot checks and coalesce concurrent in-flight `.did` fetches per canister within a script run.

### 14. [Medium] Unaudited `DID_FAILED` caching when synchronous `call_perform` fails
- **Files:** `src/lib.rs:161`, `src/bridge.rs:387-389,502-505`
- **Detail:** If both `fetch_did` sends reject synchronously before `on_first_pending` triggers, `bridge.calls() == 0` and `violations` is empty, so `run_search` skips `append_audit` while still inserting the failure into `DID_FAILED` for 5 minutes across all callers.
- **Suggested fix:** Do not negative-cache local synchronous `call_perform` refusals in `DID_FAILED`, or record an audit entry when `fetch_errors` is non-empty.

## Loop 3 — JavaScript (`Boa 0.22.0`)

### 15. [Medium] `SNAPSHOT_JS` omits `bytes > MAXB` check on object property keys
- **Files:** `src/runtimes/js.rs:75-81`
- **Detail:** `SNAPSHOT_JS` adds `bytes += k.length` for object keys without checking `if (bytes > MAXB)`, letting objects with multi-megabyte key tables bypass `MAX_VALUE_BYTES` (4 MiB).
- **Suggested fix:** Check `if (bytes > MAXB) throw new RangeError(...)` immediately after `bytes += k.length`.

### 16. [Low] `BoundedJobs::tick` checks budget only every 256 jobs; `console_fn` formats before cap
- **Files:** `src/runtimes/js.rs:108-118,234`
- **Detail:** `tick` checks `budget_error` only when `n % 256 == 0`, allowing up to 255 heavy microtasks to overrun `max_instructions`. Separately, `console_fn` evaluates `display(a, st, ctx)` for every argument before truncating `line` to `MAX_LOG_BYTES`.
- **Suggested fix:** Check `budget_error` every job (or small power of 2 / on slow jobs) and short-circuit `display` once remaining `MAX_LOG_BYTES` hits 0.

### 17. [High] Upstream Boa `0.22.0` reachable panics / capacity aborts
- **Files:** `boa_engine-0.22.0/src/builtins/string/mod.rs:541,1579`, `boa_engine-0.22.0/src/builtins/array/mod.rs:2643`, `Cargo.toml:49`
- **Detail:** `String.prototype.at` computes `-i` on `i64::MIN` (reachable via e.g. `"x".at(-1e19)`), overflowing/wrapping to an out-of-bounds index panic (`s.get_expect`). Several `Array`/`String` builtins (e.g. `sort_indexed_properties` on sparse `{ length: 2**32 - 1 }`, `padStart`/`padEnd`) call `Vec::with_capacity(len as usize)`, causing allocation panic / abort under `[profile.release] panic = "abort"`.
- **Suggested fix:** Patch/upgrade Boa (`checked_neg`, bounded capacity reservations) or avoid compiling builtins that panic on large indices.

## Loop 4 — Python (`Monty 1.6.0`) & Allocator/Time Shims

### 18. [Medium] `python::to_json` skips `budget.bytes` for big `int`s and fallback `repr` values
- **Files:** `src/runtimes/python.rs:71,84,98`
- **Detail:** `"int"` beyond `i64` (`o.py_repr()`), non-`Bytes` `"bytes"` fallback, and wildcard `_ => Value::String(o.py_repr())` never call `budget.bytes(...)`, letting values >4 MiB cross `to_json` (e.g., lists of huge `int`s).
- **Suggested fix:** Bind the formatted string to a local variable and pass `s.len()` to `budget.bytes(...)` in all three branches.

### 19. [Medium] `MAX_TURN_INSTRUCTIONS` resets on synchronous Python host turns
- **Files:** `src/runtimes/python.rs:224,251-273`
- **Detail:** `ResourceLimits::max_turn_duration` (`30B` via the `web-time` shim) resets whenever Monty resumes, even when `drive` answers synchronously without yielding to the IC (`import icp`, `icp.principal()`, cached `icp.candid()`, policy-denied `icp.call()`). A single IC message turn can burn >30B instructions (and approach 40B) if `limits.max_instructions > 30B`.
- **Suggested fix:** Track cumulative instructions consumed in the current IC turn (across synchronous resumes) or cap `limits.max_instructions` strictly <= `30B`.

### 20. [High] Upstream Monty `1.6.0` memory-limit bypasses & allocation aborts
- **Files:** `monty-1.6.0/src/modules/re.rs:207,599-637`, `monty-1.6.0/src/modules/json/dump.rs:365-373`, `Cargo.toml:49`
- **Detail:** `RePatternCache` holds up to `256 * (64 KiB + 4 KiB)` (~17.4 MiB) untracked by `ResourceTracker`, and `re.compile` allocates `HeapData::RePattern` without charging the compiled regex memory (`fancy_regex` NFA/DFA) against `max_memory`. Separately, `json.dumps(1, indent=2**31)` executes `" ".repeat(count)` without `tracker.check_allocation` or upper bound, panicking/aborting the Wasm instance.
- **Suggested fix:** Patch/upgrade `monty` to account `re` allocations and bound `json.dumps` `indent` via `tracker.check_allocation` / cap.

### 21. [Low] Test-only `COUNT_THIS_THREAD` thread-local is never reset after `python::run`
- **Files:** `src/lib.rs:368`, `src/runtimes/python.rs:201`
- **Detail:** Under `#[cfg(test)]`, `COUNT_THIS_THREAD` is set to `true` on entry to `python::run` and not restored on exit (can cause non-Python tests running later on the same worker thread to touch `LIVE_MEMORY`).
- **Suggested fix:** Use an RAII guard restoring the prior `COUNT_THIS_THREAD` value in `python::run`.

## Loop 5 — Rhai (`1.27.0`)

### 22. [High] `sleep` left enabled in Rhai `StandardPackage` (`wasm32` trap)
- **Files:** `src/runtimes/rhai_rt.rs:121,133`, `rhai-1.27.0/src/packages/lang_core.rs:138-166`
- **Detail:** Rhai gates `sleep` / `sleep_float` on `not(feature = "no_std")`, NOT `no_time`. `rhai_rt.rs` only disables `"eval"`, leaving `sleep(...)` callable. Calling `sleep(1)` executes `std::thread::sleep(...)`, which panics/traps on `wasm32-unknown-unknown`.
- **Suggested fix:** Call `engine.disable_symbol("sleep");`.

### 23. [High] `array.sort_by` swallows `on_progress` termination & aborts on comparator panic
- **Files:** `rhai-1.27.0/src/packages/array_basic.rs:1575-1600`, `Cargo.toml:49`
- **Detail:** `sort_by` discards comparator errors via `.call_raw(...).ok()`, ignoring `ErrorTerminated` from `on_progress` until sorting finishes, and uses `std::panic::catch_unwind` to guard non-total-order comparators—which does not catch panics when compiled with `panic = "abort"`.
- **Suggested fix:** Disable/override `sort` / `sort_by` or patch Rhai to propagate `EvalAltResult` and use a panic-safe comparison fallback.

### 24. [Medium] Pre-check allocation spike in `string.replace` & unbudgeted `parse_json` in Rhai
- **Files:** `src/runtimes/rhai_rt.rs:126`, `rhai-1.27.0/src/packages/string_more.rs:1177`, `rhai-1.27.0/src/packages/lang_core.rs:180-187`
- **Detail:** `string.replace(find, sub)` calls Rust `str::replace` directly before `check_data_size` runs on AST return, enabling a large single-call transient allocation spike before `max_string_size` (1 MiB) catches it. Without `rhai/metadata`, `parse_json` calls `Engine::parse_json(json, true)` allocating nested structures outside `ValueBudget`.
- **Suggested fix:** Disable/wrap `replace` to check output length before allocation and disable/wrap `parse_json` to enforce `ValueBudget`.

## Loop 6 — Demo Store (`demo_store`)

### 25. [Medium] `create_order` oversells on duplicate `product_id`s & accepts `quantity == 0`
- **Files:** `demo_store/src/lib.rs:287-298`
- **Detail:** `create_order` checks each item's `quantity <= available` independently against unchanged `inv.reserved` before adding reservations in a second loop, so duplicate `product_id` lines in `items` bypass availability checks and drive `reserved > on_hand`. `quantity == 0` line items are also accepted.
- **Suggested fix:** Reject `quantity == 0` and aggregate/check requested quantities per `product_id` before mutating `reserved`.

### 26. [Low] `demo_store` unchecked `u64` totals & case-sensitive `search_products` category
- **Files:** `demo_store/src/lib.rs:219,251-257,294`
- **Detail:** `sales_summary` and `create_order` accumulate `u64` prices/totals with `+` (`revenue += line`, `e.2 += line`, `total += ...`), wrapping silently in release builds or trapping in debug on overflow. `search_products` omits `.to_lowercase()` on `p.category` despite its doc comment `"Case-insensitive substring match on name or category"` (currently masked because `CATALOG` categories are lowercase).
- **Suggested fix:** Use `u128`/`Nat` (or checked arithmetic) for totals and compare `p.category.to_lowercase().contains(&q)`.
