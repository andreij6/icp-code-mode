2. Classic MCP vs Code Mode, side by side

Same task, same store canister, real calls on both sides. Classic MCP exposes one tool per method, and every result goes through the model. Code Mode searches once, then runs one script in the canister and sends back only the answer.

Pick a task above.
Most of Code Mode's cost is fixed: its two tool definitions, re-read every turn, plus one search. Classic MCP grows with every row and call it passes through the model, so the gap widens with real data volumes. This demo store has only 60 orders.

      How the numbers are counted
      
        
      Real: every call on both sides runs against the canister, so the call counts, the results (in characters) and the
        canister time are measured. On the Classic side, each tool call is run as its own one-call script, so its result is exactly
        what a per-method tool would return.
      
        
      Modelled: an agent loop where each LLM turn re-reads its whole context: the tool definitions, the task, and every
        earlier tool call and result. Classic tool definitions are built from the store's real Candid interface: 10 tools, each with
        its signature and referenced types (a lower bound; JSON Schemas are usually larger). Code Mode's definitions are this server's
        real tools/list. On the Classic side, the page does the model's work between turns (ranking, filtering) only to
        decide which calls come next.
      
        
      Estimated: tokens ≈ characters ÷ 4. Model latency is not included; every extra LLM round trip adds it.
